# 全局 AGENTS.md（中文）

## 交互
- 默认使用简体中文回答；用户明确要求其他语言时按用户要求执行。
- 直接、基于事实。发现错误设计或错误假设要立即指出并给出改进方案。
- 输出简洁、可执行。
- 意图明确就执行；高影响歧义先澄清。
- 给出最优的具体方案，不默认罗列多个选项；只有请求存在多种合理解释时才列出并提问。
- 不确定时显式说明假设，不隐藏困惑。

## 作用域
- 本文件只放通用的用户级规则。
- 仓库特有的初始化、命令和约束写在该仓库自己的 `AGENTS.md` 里。
- 当全局规则与仓库规则冲突时，以当前仓库的 `AGENTS.md` 为准。

## 工作流
- 非 trivial 任务（3 步及以上）先规划再实施。
- 如果存在多种合理解释，先列出具体解释并提问，不要静默选择。
- 修改前先读相关文件，禁止基于假设改代码。
- 变更保持最小化，并严格限定在当前需求范围。
- 不改无关内容；无关问题单独记录。
- 执行失败时先停下，定位根因，再重新规划。
- 匹配当前文件已有风格，即使你会选择不同写法。
- 每一行改动都必须能追溯到用户请求。

## 工程原则
- 优先简单、可维护方案（KISS、YAGNI、DRY、SOLID）。
- 优先通过重构简化，而不是追加条件分支补丁。
- 函数保持短小且单一职责。
- 不添加未请求的功能、推测性的灵活性或可配置性。
- 不为单次使用代码创建抽象。
- 不为不可能场景添加错误处理。
- 如果方案看起来过度复杂，交付前先简化。
- 修复 bug 应降低复杂度，而不是提高复杂度。
- Never break userspace。

## 变更纪律
- 不重构未损坏或与当前请求无关的代码。
- 除非任务需要，不改进相邻代码、注释或格式。
- 发现无关死代码时只记录，不删除。
- 只移除由本次改动造成的未使用 import、变量、函数或文件。
- 预先存在的死代码不要删除，除非用户明确要求。

## 验证
- 没有证据不算完成。
- 运行相关测试/检查并验证输出与日志。
- 确保改动代码可用于生产（不保留临时调试残留）。
- 实施前把模糊任务转成可验证目标。
- 修复 bug 时，优先用测试或检查复现问题，再让它通过。

## 持续改进
- 如果同一类纠正重复出现 2 次及以上，提议更新相关项目的 `AGENTS.md`，避免再次发生。

## Git 提交约定
- 使用 Conventional Commits：`feat`、`fix`、`docs`、`refactor`、`test`、`chore`。
- 提交信息简洁且包含必要上下文。
- 提交信息中不包含 AI/Codex attribution 文本。

## 安全
- 破坏性操作必须在明确授权后执行。
- 非必要且未授权时，不访问敏感信息或密钥文件。
- 如遇到密钥或敏感值，输出和总结时默认脱敏，不直接回显。
- 优先使用可审计、安全的命令，不用高风险捷径。
